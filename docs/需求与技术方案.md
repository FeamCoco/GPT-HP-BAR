# GPT-HP-BAR · 需求与技术方案

> 一个 Windows 常驻小工具：实时显示 ChatGPT 账号下 **Codex（CLI 与桌面版共用同一账号池）** 的剩余额度。
> 双形态展示：**桌面悬浮窗 + 任务栏/托盘**，支持字体、配色、额度样式等自定义。
> 版本 v0.2 · 2026-09-06

---

## 1. 背景调研结论（含本机实测）

### 1.1 ChatGPT 桌面版 与 Codex CLI 确实是"同一个"

- 本机实测：`~/.codex/.codex-global-state.json` 内含大量 `electron-main-window-bounds`、`chatgpt-migration-announcement-*` 等键——**ChatGPT 桌面版（Electron 壳）与 Codex CLI 共用同一个 `CODEX_HOME`（`~/.codex`）**，共用同一份登录态与额度。
- 因此**监控一份即可覆盖两者**：额度挂在 ChatGPT 账号（订阅计划）上，不区分入口。

### 1.2 "额度"到底是什么

| 额度类型 | 含义 | 典型字段 |
|---|---|---|
| **5 小时窗口**（primary） | 滚动 5h 用量限制，Codex 密集使用时触发 | `primary_window.used_percent`、`window_minutes=300`、重置时间 |
| **每周窗口**（secondary） | 周级总量限制 | `secondary_window.*`、`window_minutes=10080` |
| **API 余额 / credits** | 按量付费余额（有则显示） | `balance`、`hasCredits`、`unlimited` |
| 模型专属窗口 | 如 Codex-Spark 等额外限制 | `additional_rate_limits[]` |

### 1.3 数据从哪来（按优先级）

1. **首选：Codex CLI 自带的 app-server JSON-RPC**
   `codex -s read-only -a never app-server`，调用 `account/read`（邮箱+plan 类型）与 `account/rateLimits/read`（窗口用量、credits `balance/hasCredits/unlimited`）。
   优点：官方进程、**token 续期由 Codex CLI 自己处理**（我们不去碰 auth.json 的写逻辑）、鉴权模式无关。
2. **备选：直连 REST**
   读 `$CODEX_HOME/auth.json`（Windows: `C:\Users\<user>\.codex\auth.json`）取 `tokens.access_token` →
   `GET https://chatgpt.com/backend-api/wham/usage`，头 `Authorization: Bearer <token>`。
   响应解析需**宽容兼容**：`rate_limit` / `rate_limits` 两种拼写、`primary_window/secondary_window`、`additional_rate_limits[]`。
   token 过期 → `POST auth.openai.com/oauth/token`（`grant_type=refresh_token`，client_id 与 Codex CLI 一致，见 codex-rs/login 源码，实现时以源码为准）。
3. **中转 / API-key 模式（本机现状）**
   实测本机 `config.toml` 含 `base_url`、`experimental_bearer_token` 键，`auth.json` 仅 46 字节——即走的是**中转（relay）而非 ChatGPT OAuth 登录**。
   策略：读 `base_url` 后探测 `{base}/backend-api/wham/usage` → `{base}/wham/usage`；都失败则允许用户在设置里手填"用量接口 URL + Header"（很多中转面板自带用量接口）。
4. **兜底**：全部失败 → 显示"未登录 / 无数据源"，一键手动刷新 + 指引。

### 1.4 风险与对策

- `wham/usage` 是**非公开接口**，字段可能变 → 解析器做成宽容映射 + 保留原始 JSON 便于排查。
- Codex CLI 升级可能改 auth.json 结构 → 优先走 app-server（CLI 自己兼容自己）。
- 轮询频率默认 **60s**（可调 30s~10min）；401 时立即刷新重试；连续失败指数退避；支持手动刷新。
- 不上传任何数据，纯本地；日志不落 token。

## 2. 功能需求

### P0（首版必须）

- **悬浮窗**：始终置顶、无边框、可拖拽、边缘吸附（贴屏幕四边）、透明度可调、**鼠标穿透开关**、点击展开详情（双窗口 + 重置倒计时）。
- **任务栏/托盘**：托盘图标**动态绘制迷你额度条**（16×16 自绘）+ 悬停 tooltip（两窗口明细）+ 右键菜单（刷新/皮肤/设置/退出）。
- **数据**：5h 剩余%、周剩余%、重置倒计时、plan 徽标（Plus/Pro/Team）；低额度（默认 <20%）红色高亮 + 可选通知。
- **5 套样式皮肤**（见设计稿），一键切换。

### P1（第二批）

- Windows 11 **任务栏窗口嵌入**（TrafficMonitor 式，实验性，Explorer 更新可能失效，故托盘形态为保底）。
- credits 余额显示、`additional_rate_limits`（Spark 等模型窗口）。
- 用量历史 sparkline（本地记录，%APPDATA%/GPT-HP-BAR/history.json）。
- 开机自启、主题跟随系统深浅色、多账号（多份 auth 备份）切换。

### P2

- 全局热键呼出/隐藏、重置前用量预测曲线、用量导出 CSV。

### 设置项（用户点名）

| 类别 | 项 |
|---|---|
| **字体** | 枚举系统任意字体、字号、字重、字距 |
| **额度样式** | 5 套皮肤、血条配色与渐变阈值（绿→黄→红分界可调）、圆角、描边、阴影、宽度、透明度 |
| **内容开关** | 5h 窗口、周窗口、credits、倒计时、plan 徽标、图标 |
| **行为** | 刷新间隔、鼠标穿透、边缘吸附、开机自启、低额度提醒阈值、任务栏位置（左/中/右 + 偏移微调）、任务栏冲突避让开关 |

## 3. 技术选型

| 方案 | 体积 | 悬浮窗/透明 | 托盘 | 任务栏嵌入 | 皮肤开发效率 | 结论 |
|---|---|---|---|---|---|---|
| **Tauri 2 (Rust + WebView2)** | ~5MB | ✅ 原生支持 | ✅ | 中（Win32 互操作可做） | ★★★ HTML/CSS 即皮肤 | **推荐** |
| Electron | ~150MB | ✅ | ✅ | 难 | ★★★ | 太重，弃 |
| C# WPF (.NET 8) | ~70MB(单文件) | ✅ | ✅ | ★★ 最顺（原生 Win32） | ★★ XAML | 备选（若死磕任务栏嵌入） |
| Qt (PySide/C++) | ~40MB | ✅ | ✅ | 中 | ★★ | 一般 |
| Python + pystray | ~30MB | 一般 | ✅ | 难 | ★ | 仅原型 |

**推荐：Tauri 2**。决定性理由：**设计稿即实现**——本项目的 5 套皮肤本来就是 HTML/CSS，Tauri 前端可直接复用设计稿代码；Rust 后端负责轮询/解析/缓存；Win32 侧做托盘自绘与（实验性）任务栏嵌入。

```
┌────────────────────────── GPT-HP-BAR.exe (Tauri 2) ──────────────────────────┐
│  Rust 后端                                                                   │
│   ├─ 采集器: app-server RPC ─ REST(wham/usage) ─ 中转探测 ─ 自定义接口        │
│   ├─ 缓存/退避/Token 续期     ├─ 历史记录 (history.json)                      │
│   └─ Win32: 托盘图标自绘 · 置顶窗 · 鼠标穿透 · (实验)任务栏嵌入 · 自启        │
│            ▲▼ IPC (事件推送: usage_update / error)                           │
│  WebView 前端 = 设计稿同源代码                                                │
│   ├─ 悬浮窗 (无边框置顶窗, 5 套皮肤 CSS)   ├─ 设置面板 (字体/配色/行为)        │
│   └─ 详情弹层 (双窗口/倒计时/sparkline)    └─ 托盘菜单 (原生)                  │
└──────────────────────────────────────────────────────────────────────────────┘
```

## 6. 任务栏显示：位置与冲突规避（开源调研）

### 6.1 开源实现调研结论（2026-09-06，TrafficMonitor 源码 + 方案比对）

**A. 托盘图标（NotifyIcon）** — 通知区域由 Shell 管理，天然无冲突，作为保底形态（P0）。

**B. 任务栏窗口（TrafficMonitor 路线，MIT 许可，可参考实现）**，源码分三套对话框：
- **Win10 经典任务栏**（`ClassicalTaskbarDlg.cpp`）：
  在 `Shell_TrayWnd` 下找 `ReBarWindow32`（退化时 `WorkerW`），再取任务按钮区 `MSTaskSwWClass`（退化 `MSTaskListWClass`）；
  **收缩任务按钮区宽度，把腾出的空间留给自己**（`MoveWindow(m_hMin, ..., 宽-自宽)`），加 2px 间距，退出时按 `m_rcMinOri` 恢复原矩形。
  支持 taskbar 在上/下/左/右四边（按宽高比判断：`rect.Width() >= rect.Height()`），横向任务栏裁宽度、纵向裁高度并留 `DPI(2)` 边距。
- **Win11 新任务栏**（`Win11TaskbarDlg.cpp`）：`ReBarWindow32` 已不存在，改为**作为 `Shell_TrayWnd` 的子窗口浮在 XAML 内容之上**，定位锚点用两个仍然存在的同层子窗口：
  - `TrayNotifyWnd`（托盘/时钟区）与 `Start`（开始按钮）
  - **靠右（默认）**：`x = TrayNotifyWnd.left − 自宽 + 2px`
  - **靠左**：`x = Start.right + 2px`（或贴左 2px），另有 DPI 缩放的用户偏移量 `window_offset_left` 微调
  - **重算触发**：`TrayNotifyWnd` 宽度变化（托盘图标增删）、`Start.left` 变化（任务栏对齐方式切换）、手动强制刷新
  - **已知坑（源码印证）**：副屏没有 `TrayNotifyWnd` → 按 88px 时钟宽度估算或读配置 `taskbar_right_space_win11`；
    Win11 build 22621+ 触屏设备有垂直偏移 → 垂直居中改用 `Start` 高度做基准；Win11 任务栏恒为底部，不做四边判断；
    Win11 任务栏图标居中时"左侧"配置会被强制回右侧。
- **Wine 环境**另有 `WineTaskbarDlg.cpp`（我们不需要）。
- TrafficMonitor 未做"居中"位置（只有左/右+偏移）；居中可自行计算：`x = 任务栏宽/2 − 自宽/2`，但 Win11 默认图标居中，**中位必须避让居中图标组**，实际应落在图标组右/左侧最近空闲区。

**C. Explorer 注入 + XAML Hook（Windhawk mod 路线，如 Taskbar Clock Customization）**
注入 explorer.exe，直接改 XAML 任务栏内部文本元素，能做到"看起来是任务栏原生的一部分"，位置随意（左/中/右）。
代价：随系统更新极易碎、杀软误报、维护成本高 → 本项目仅列为 P2 可选实验模块，不进主线。

### 6.2 本项目的冲突规避算法（设计）

目标：与 TrafficMonitor、网速球、音量挂件等**第三方任务栏窗口**共存，支持左/中/右三档位置。

1. **占用收集**（每次布局时）：
   - `Shell_TrayWnd` 全部子窗口矩形：`Start`、`TrayNotifyWnd`、任务按钮区、XAML 内容宿主窗口；
   - 枚举所有可见 top-level 窗口，凡矩形与任务栏条带相交者视为第三方挂件（TrafficMonitor 类工具、托盘增强等）；
   - 我们自己上一次的矩形（避免自遮挡）。
2. **空闲区间** = 任务栏水平带 − 全部占用区间（DPI 换算，区间间保留 2px 间距）。
3. **选位**：按请求锚点（左/中/右）找该方向最近的可容纳区间 → 找不到则依次尝试其他锚点 → 仍无 → 降级显示（隐藏副信息/只留数字）→ 最终回退托盘图标形态并气泡提示一次。
4. **重算时机**：`TaskbarCreated` 广播消息；500ms 轮询比对 `TrayNotifyWnd` 宽度与 `Start.left`（同 TrafficMonitor 的变化检测思路）；`WM_SETTINGCHANGE`；DPI/分辨率变化；任务栏自动隐藏展开时。
5. **多屏**：默认只驻主屏任务栏；副屏可选开启，按"88px 时钟估算"处理（TrafficMonitor 同款兜底）。
6. **退出安全**：与 TrafficMonitor 相同，记录被我们改变的区域原值，退出时恢复（Win10 收缩模式必需）。

设计稿中的"任务栏靠左/居中/靠右 + 第三方冲突演示"已按本算法的**简化 DOM 版**实现：实测任务栏内各占用区间 → 求空闲区间 → 在请求锚点方向选最近可容纳位 → 动画滑入，红斜纹实时标出被占用区域；无处安放时警示（应用中此分支回退托盘图标形态）。
