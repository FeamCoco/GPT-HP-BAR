# 模型用量统计 + 当前 token 速度 · 设计与实现（v0.6）

> 2026-11-04 立项并实现。两个新能力：
> ① **模型用量统计** —— 今日 / 近 7 天，每个模型各跑了多少 token；
> ② **当前 token 速度** —— 实时 tok/s，按速度映射成载具档位（🐢🚲🛵🚗🚄🚀）。
>
> "区分单车/摩托车"这套隐喻借鉴自社区项目（他们用载具图标表示网速/token 速度），
> 本文按本项目的架构（Rust 数据层 + 皮肤契约 + i18n 字典）重新设计接入方式。

---

## 1. 数据从哪来：本机 Codex 会话记录，零新接口

额度数据（5h/周窗口）来自 wham/usage / app-server / 中转，但它们**不含 token 数**。
而 Codex CLI / ChatGPT 桌面版本来就把每轮对话写到本地会话记录：

```
$CODEX_HOME/sessions/YYYY/MM/DD/rollout-<时间戳>-<uuid>.jsonl
```

每行一条 JSON，与本功能相关的四类：

| type | payload 关键字段 | 用途 |
|---|---|---|
| `token_usage_record` | `usage{input/cached/output/reasoning/total}`, `turn_id`, `response_id` | 单响应用量（新版 CLI，**权威口径**） |
| `event_msg` + `token_count` | `info.last_token_usage`（单响应增量）、`info.total_token_usage`（线程累计） | 老版 CLI 的用量来源 + **速度采样** |
| `turn_context` | `model`, `turn_id` | 模型归属 |
| `event_msg` + `thread_settings_applied` | `thread_settings.model` | 模型归属兜底 |

结论：**增量 tail 这些 JSONL 即可**，纯本地、零上传，且与额度数据源完全解耦 ——
中转 / API-key 账号没有 5h 窗口，也能在这里看到自己真实跑了多少 token。

实现：`app/src/stats.rs`（独立于 datasource.rs；额度取数失败不影响用量统计，反之亦然）。

## 2. 增量扫描（能每 2 秒跑一轮的原因）

`stats::Scanner` 给每个文件记 `{offset, mtime, 聚合}`：

- **未变化**（`size == offset && mtime 未变`）→ 一次 stat 比对就跳过，零读取；
- **追加** → `seek(offset)` 只读新增字节，**只消费到最后一个完整行**
  （写进程可能正在写半行，半行留给下一轮，绝不丢也不重）；
- **截断/重写**（`size < offset`）→ 该文件状态整体重置从头读，绝不重复计数；
- **同文件去重**：`token_usage_record` 按 `response_id` 去重；
- **口径二选一**：文件里有 `token_usage_record` 就只用它（新版 CLI 两类都写，
  同一批用量在 `token_count` 里会再出现一次，混用直接翻倍）；没有才退回 `token_count`；
- **老目录的长会话靠 mtime 入选**：日期目录出窗（如 10/17 开的会话一路追加到 10/31）
  时不能整目录跳过 —— 只要文件 mtime 还在窗口内就收进来。实机验证时靠独立
  Python 交叉核对抓到过这个洞（gpt-6.1-sol 的 366k tok 因此漏计）；
- **窗口**：本地今天 + 近 7 天（8 天）；窗口外的文件状态整体释放。
  修剪线比快照窗口早 1 天，跨午夜的长会话昨天入的账今天还能继续读到增量；
- "今天"的口径是**本地时区**（记录时间戳是 UTC）：早上 8 点前不能把昨晚算进今天。
  时区换算交给 chrono（`Local`），夏令时等细节不用自己扛。

并发多会话（主任务 + guardian/reviewer 子代理）就是多个文件，各扫各的；
速度取"最近还有事件"的那个文件。

## 3. 当前 token 速度的语义

```
速度 = Σ(相邻两次响应完成之间的输出 token 增量) / Σ(时间差)，滚动 2 分钟窗口
```

- 用 `info.total_token_usage.output_tokens` 的**累计值**做差分（老版没有累计，
  退回运行累加）；只算**输出**（含推理 token，它们本来就是 output 的子集）；
- 窗口内不足两个采样点 → `speed_tok_s = None`，**不硬编 0**：
  响应间隔可能被工具调用拉长几分钟，硬算会得到误导性的"接近 0"；
- 活跃判定独立于速度：最近一次 token 事件 ≤ 3 分钟就算 `active`
  （此时哪怕速度暂缺，UI 也显示"生成中…"的等待态）；
- 阈值标定：Codex 的响应间隔含工具调用往返，本机观测有效输出速度多落在
  20~150 tok/s，>300 已是极快的连续输出。

### 载具档位（前端 i18n.js `speedTier`）

| tok/s | <15 | <40 | <80 | <150 | <300 | ≥300 |
|---|---|---|---|---|---|---|
| 图标 | 🐢 | 🚲 | 🛵 | 🚗 | 🚄 | 🚀 |
| zh | 乌龟 | 单车 | 摩托 | 汽车 | 高铁 | 火箭 |
| en | Turtle | Bicycle | Motorbike | Car | Bullet train | Rocket |

Rust 只出数字，图标与名称是纯前端展示层 —— 想换隐喻（比如换成游戏坐骑）只动 i18n.js。

## 4. 接入面（都走本项目既有模式）

| 面 | 实现 |
|---|---|
| **数据线程** | `main.rs` setup 里新增 stats 线程：每 2s 扫增量；数据变化或活跃 → `emit("stats")`；全静默退化为 30s 心跳。与额度轮询线程互不阻塞 |
| **用量面板** | 新窗口 `stats.html`（与设置窗口同款 hide-on-close 模式）：速度卡（载具大图标 + tok/s）、今日 24 小时分布柱状图、今日/近 7 天模型表（输入含缓存、输出、合计、响应数、占比条） |
| **托盘菜单** | 新增「模型用量…」（`open_stats` 命令，文案随语言） |
| **悬浮窗** | chrome 注入第三个按钮 📊（外壳层，10 套皮肤零改动全都有入口）；card（默认皮肤）foot 行加 `.hp-speed` 徽标，活跃时显示 `🛵 86 t/s` |
| **设置面板** | 数据源节新增「模型用量…」按钮 |
| **探针** | `--probe-stats`：无 GUI 打印会话文件数 / 各模型用量 / 速度 / 小时分布（纯本地，无密钥输出） |
| **i18n** | `st_*` 系列键 + `spd_names`，中英对照 |

速度徽标的刷新纪律（写进了 common.js 注释）：`stats` 事件**只直填 `.hp-speed`**，
不做整卡重渲染 —— stats 事件比 usage 密得多（活跃时 2s 一次），整卡重画会让
`HP.tween` 数值补间和一次性动效不停重启。

## 5. 已知边界

- **模型归属**是启发式：`token_count` 不带 turn_id，归属"文件里最近一次
  turn_context/settings 的模型"；归不上的进「未知模型」，宁可显示未知也不丢数字。
- resume 出来的新会话文件只含新事件（codex 0.166 实测），不做跨文件去重；
  若未来 CLI 改为复制历史，`response_id` 去重只在单文件内生效，可能重复计数（观测点）。
- 子代理（如 `codex-auto-review`）的会话是独立文件，一样计入 —— 它们确实在花同一账号的额度。
- 会话文件缺模型字段的极端情况按 `unknown` 处理。
- 前端（面板/徽标/档位）无法在沙箱里活体验证，需实机验收（见 §6）。
